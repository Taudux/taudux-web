Módulo 1 — Fundamentos

Qué es SQL, de dónde viene, cómo se organiza una base de datos y una idea clave que evita el 80 % de los errores de principiante.

1.1 · ¿Qué es SQL?

SQL = Structured Query Language (Lenguaje de Consulta Estructurado).

Es un lenguaje declarativo: le dices a la base qué quieres, no cómo buscarlo. Sirve para guardar, consultar y modificar datos organizados en tablas relacionadas entre sí.

Ejemplo — pedir los clientes de Querétaro. No programas ningún recorrido; solo describes el resultado:

SELECT nombre
FROM clientes
WHERE ciudad = 'Querétaro';
Analogía

Es como pedir en un restaurante ("quiero los tacos, sin cebolla") en lugar de entrar a la cocina a prepararlos. Tú dices el qué; el motor se encarga del cómo.

1.2 · ¿Desde cuándo y por qué?

  • 1970 — Edgar F. Codd (IBM) publica el modelo relacional: organizar los datos en tablas y consultarlos con álgebra, en lugar de seguir "punteros" físicos.
  • 1974 — Donald Chamberlin y Raymond Boyce (IBM, San José) crean SEQUEL para llevar el modelo de Codd a la práctica, dentro del proyecto System R. Más tarde se renombra SQL por un conflicto de marca.
  • 1979 — Oracle lanza el primer motor relacional comercial. 1986 — se vuelve estándar ANSI (ISO en 1987).

¿Por qué fue importante? Antes, consultar datos exigía saber cómo estaban guardados físicamente y programar el recorrido. SQL separó "qué pido" de "cómo se busca": cualquiera puede consultar sin ser programador de bajo nivel.

Fuentes

Codd, E. F. (1970), A Relational Model of Data for Large Shared Data Banks, Communications of the ACM · Chamberlin, D. & Boyce, R. (1974), SEQUEL: A Structured English Query Language, ACM SIGFIDET.

1.3 · El modelo relacional: tablas, filas y columnas

Los datos viven en tablas. En una tabla:

  • Fila (registro) = una entidad concreta → un cliente.
  • Columna (campo) = una propiedad → nombre, ciudad.

Ejemplo de la tabla clientes:

id_cliente nombre ciudad
1 Ana López Querétaro
2 Luis Márquez Monterrey
3 Sara Ortiz Querétaro

La columna que identifica de forma única cada fila es la clave primaria (PK) → aquí, id_cliente.

1.4 · Relaciones, claves y tipos de dato

  • Clave foránea (FK): una columna que apunta a la PK de otra tabla. Así se relacionan las tablas: un pedido "pertenece a" un cliente.
  • Integridad referencial: no puede existir un pedido de un cliente que no existe.
  • SGBD (Sistema Gestor de Bases de Datos): el software que administra todo esto → PostgreSQL, MySQL, SQL Server, SQLite, Oracle. En este curso usamos PostgreSQL.
  • Tipos de dato: cada columna tiene un tipo (entero, texto, fecha, booleano, decimal) que define qué se puede guardar y qué operaciones se permiten.
Idea para llevarse

Una base de datos relacional es un conjunto de tablas conectadas por claves. SQL es el idioma para leerlas y modificarlas.

1.5 · ¿Qué es DDL y qué es DML?

Dos familias de comandos que hay que distinguir desde el inicio:

DDL — Data Definition Language → define la estructura (el "molde" de las tablas):

CREATE TABLE clientes (
  id_cliente INT PRIMARY KEY,
  nombre     TEXT,
  ciudad     TEXT
);

DML — Data Manipulation Language → maneja los datos dentro de las tablas:

INSERT INTO clientes (id_cliente, nombre, ciudad)
VALUES (1, 'Ana López', 'Querétaro');

¿Por qué importan? DDL crea el recipiente; DML lo llena y lo mantiene. Sin ellos no habría datos que consultar: cuando hacemos SELECT, leemos lo que DDL definió y DML pobló.

1.6 · Los sublenguajes de SQL: todo lo que se puede hacer

SQL no es solo SELECT. Todo lo que ocurre en una base de datos cae en una de cinco categorías:

Sublenguaje ¿Para qué sirve? Comandos típicos
DQL Consultar (leer) SELECT
DML Manipular datos INSERT, UPDATE, DELETE
DDL Definir la estructura CREATE, ALTER, DROP, TRUNCATE
DCL Permisos y seguridad GRANT, REVOKE
TCL Control de transacciones BEGIN, COMMIT, ROLLBACK

En este curso nos enfocamos en DQL (consultas) y tocamos DML/DDL. DCL y TCL (administración) quedan para un curso avanzado.

1.7 · Concepto clave: escribir ≠ ejecutar

El orden en que escribes una consulta no es el orden en que la base la ejecuta.

Orden en que se escribe:

SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT

Orden en que realmente se ejecuta (orden lógico):

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
El error clásico
SELECT precio * cantidad AS total
FROM ventas
WHERE total > 1000;   -- ❌ ERROR: la columna "total" no existe

Si se ejecutara en el orden escrito, el alias total (definido en el SELECT) ya existiría al llegar al WHERE. Pero como el WHERE se ejecuta antes que el SELECT, el alias todavía no nace → error.

Forma correcta (repites la expresión, porque el WHERE aún no conoce el alias):

SELECT precio * cantidad AS total
FROM ventas
WHERE precio * cantidad > 1000;

Regla mental: el FROM y el WHERE ocurren primero; el SELECT y sus alias, casi al final.

2.1 · SELECT, FROM y el asterisco *

SELECT nombre, precio FROM productos; -- solo lo que interesa

2.2 · Alias con AS: renombrar columnas y tablas

  • AS cambia el nombre de una columna en el resultado (encabezados más claros) o de una tabla (un apodo corto).

SELECT nombre AS producto,
       precio AS "precio en MXN"
FROM productos;

SELECT p.nombre, p.precio      -- apodo (alias) de tabla
FROM productos AS p;

2.3 · Columnas calculadas: expresiones en el SELECT

En el SELECT no solo eliges columnas: también puedes calcular valores nuevos.

  • Aritmética: precio * 1.16, precio * stock, etc.
  • Texto: se une con el operador ||.

       precio,
       precio * 1.16 AS precio_con_iva
FROM productos;

SELECT nombre || ' (' || ciudad || ')' AS cliente_ciudad
FROM clientes;

Módulo 3 — Filtrado con WHERE

Quedarnos solo con las filas que cumplen una condición.

3.1 · Operadores de comparación

WHERE conserva las filas que cumplen una condición. Los operadores de comparación son:

Operador Significado
= igual
<> o != distinto
< > menor / mayor
<= >= menor-igual / mayor-igual

El texto va entre comillas simples: 'Querétaro'.

SELECT nombre, precio FROM productos
WHERE precio > 1000;              -- mayor que

SELECT id_pedido, estado FROM pedidos
WHERE estado <> 'entregado';      -- distinto de (los demás operadores se usan igual)

3.2 · Operadores lógicos: AND, OR, NOT

Combinan varias condiciones:

  • AND → deben cumplirse todas.
  • OR → basta con que se cumpla una.
  • NOT → niega una condición.
SELECT nombre FROM productos
WHERE id_categoria = 1 AND precio < 1000;        -- AND: se cumplen las dos

SELECT nombre FROM clientes
WHERE ciudad = 'Querétaro' OR ciudad = 'CDMX';   -- OR: basta con una

SELECT nombre FROM productos
WHERE NOT activo;                                -- NOT: niega la condición (los inactivos)
Cuidado con la precedencia

NOT se evalúa antes que AND, y AND antes que OR. Cuando mezcles AND con OR, usa paréntesis para dejar clara tu intención:

-- ¿"(A y B) o C"  o  "A y (B o C)"? El paréntesis lo decide.
WHERE (ciudad = 'Querétaro' OR ciudad = 'CDMX') AND precio < 1000

Módulo 4 — Rangos y patrones

Formas más cómodas de filtrar: listas de valores, rangos y patrones de texto.

4.1 · IN y NOT IN

IN comprueba si un valor está en una lista (más limpio que muchos OR). NOT IN hace lo contrario.

SELECT nombre, ciudad FROM clientes
WHERE ciudad IN ('Querétaro', 'CDMX');       -- está en la lista

SELECT nombre, id_categoria FROM productos
WHERE id_categoria NOT IN (1, 2);            -- NO está en la lista

Solución

Problema 2

Muestra los pedidos cuyo estado sea 'pendiente' o 'cancelado', usando IN.

Solución

4.2 · BETWEEN

BETWEEN a AND b selecciona los valores dentro de un rango, incluyendo ambos extremos. Funciona con números y también con fechas.

SELECT nombre, precio
FROM productos
WHERE precio BETWEEN 500 AND 2000;                         -- números

SELECT id_pedido
FROM pedidos
WHERE fecha_pedido BETWEEN '2024-01-01' AND '2024-06-30';  -- fechas
¿Cómo se escribe una fecha? Usa siempre formato ISO

Una fecha se escribe como texto entre comillas simples, y la regla de oro es usar siempre el formato ISO 8601: 'AAAA-MM-DD' (año-mes-día). Ejemplo: '2024-08-01'. Como la columna fecha_pedido es de tipo DATE, PostgreSQL entiende que ese texto es una fecha de forma automática: no hace falta nada más.

¿Por qué ISO y no '01/08/2024'? Porque el formato ISO es el estándar internacional y no es ambiguo: '01/08/2024' puede leerse como 1 de agosto o como 8 de enero según la configuración del servidor, mientras que '2024-08-01' significa lo mismo en cualquier lado. Además, escrito así, las fechas se ordenan igual que en el calendario. Si quieres dejar el tipo explícito, puedes escribir DATE '2024-08-01'; es equivalente y ambas formas funcionan igual.

5.2 · LIMIT y OFFSET

  • LIMIT n devuelve solo las primeras n filas.
  • OFFSET k se salta las primeras k filas.
  • Juntos (LIMIT n OFFSET k) sirven para paginar: mostrar los resultados de a "páginas".
SELECT nombre, precio
FROM productos
ORDER BY precio DESC
LIMIT 3;                 -- los 3 más caros (1.º al 3.º)

SELECT nombre, precio
FROM productos
ORDER BY precio DESC
OFFSET 3;                -- se salta los 3 más caros y muestra el resto

SELECT nombre, precio
FROM productos
ORDER BY precio DESC
LIMIT 3 OFFSET 3;        -- del 4.º al 6.º más caro (la "segunda página" de 3)
Paginación

Así funcionan las páginas de resultados de una tienda o un buscador. Con páginas de 3 en 3: la página 1 es LIMIT 3 OFFSET 0, la página 2 es LIMIT 3 OFFSET 3, la página 3 es LIMIT 3 OFFSET 6… La fórmula del salto es OFFSET = (número_de_página − 1) × tamaño_de_página. Siempre con ORDER BY: sin un orden fijo, "saltar las primeras 3" no significa nada, porque la base no garantiza en qué orden salen las filas.

WHERE fecha_envio IS NOT NULL;   -- pedidos que ya se enviaron
Nunca = NULL

WHERE telefono = NULL no da error, pero nunca devuelve filas: cualquier comparación con NULL da "desconocido", no "verdadero".

7.1 · Funciones de texto

SELECT nombre,
       UPPER(nombre)  AS en_mayusculas,

SELECT email,
       REPLACE(email, '@mail.com', '') AS usuario,     -- reemplaza texto por otro

       TRIM('   hola   ')              AS sin_espacios  -- quita espacios de los extremos
FROM clientes;

Módulo 8 — Agregación y agrupamiento

Resumir muchos datos en un solo valor: conteos, sumas, promedios… y hacerlo por grupos.

8.1 · Funciones de agregación y DISTINCT

Resumen un conjunto de filas en un valor: COUNT, SUM, AVG, MIN, MAX.

  • COUNT(*) cuenta filas; COUNT(columna) ignora los nulos de esa columna.
  • DISTINCT elimina repetidos: COUNT(DISTINCT ciudad) cuenta ciudades diferentes.
-- Las cinco funciones de agregación en una sola consulta
SELECT COUNT(*)    AS cuantos,
       SUM(precio) AS suma,
       AVG(precio) AS promedio,
       MIN(precio) AS mas_barato,
       MAX(precio) AS mas_caro
FROM productos;

-- DISTINCT: cuenta cuántos valores DIFERENTES hay

9.2 · LEFT JOIN (y outer joins)

Un LEFT JOIN conserva todas las filas de la tabla izquierda, aunque no tengan pareja a la derecha (esas filas traen NULL en las columnas de la derecha). Sirve para responder "¿quién no tiene…?".

  • RIGHT JOIN: igual, pero conserva la tabla derecha.
  • FULL OUTER JOIN: conserva ambas.
SELECT cl.nombre, pe.id_pedido
FROM clientes cl
LEFT JOIN pedidos pe ON cl.id_cliente = pe.id_cliente;

-- RIGHT JOIN: el espejo del LEFT (conserva la tabla de la derecha)
SELECT cl.nombre, pe.id_pedido
FROM pedidos pe
RIGHT JOIN clientes cl ON pe.id_cliente = cl.id_cliente;

-- FULL OUTER JOIN: conserva las filas de AMBAS tablas
SELECT cl.nombre, pe.id_pedido
FROM clientes cl
FULL OUTER JOIN pedidos pe ON cl.id_cliente = pe.id_cliente;

11.3 · Subconsultas en el FROM (tablas derivadas)

Una subconsulta en el FROM se comporta como una tabla temporal (una "tabla derivada"): le pones un alias y consultas sobre ella. Es una de las cosas que se llaman "tablas virtuales".

SELECT categoria, num_productos
FROM (
  SELECT id_categoria AS categoria, COUNT(*) AS num_productos
  FROM productos
  GROUP BY id_categoria
) AS resumen
WHERE num_productos > 3;
